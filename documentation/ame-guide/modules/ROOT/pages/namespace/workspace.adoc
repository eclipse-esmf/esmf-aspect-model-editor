[[workspace-directory]]
= Workspace directory

The workspace is a simple folder structure on your local machine.

By default, the Aspect Model Editor file directory is located at following path:

* `+C:\Users\<YOUR-USER-NAME>\aspect-model-editor+` (on Windows)
* `+/Users/<YOUR-USER-NAME>/aspect-model-editor+` (on MacOs )
* `+/home/<YOUR-USER-NAME>/aspect-model-editor+` (on Linux)

On your local file directory, you can manually add, edit, and delete the folder structure for all your Aspect Models.

Of course, this is also possible with the Aspect Model Editor. The same folder structure is displayed in the xref:getting-started/ui-overview.adoc#workspace-sidebar[Workspace sidebar].

image::namespace-file-structure.png[width=85%, link=self]

NOTE: Namespaces that do not follow this file structure might not work and might break the xref:namespace/use-references.adoc[references] feature.

== Action dialog in workspace

The currently loaded Aspect Model is highlighted gray.

The three-dot menu next to a model offers the options:

* *Open in new window*: to open the Aspect Model in a new window
* *Open in current tab*: to replace the Aspect Model of the active tab. If the active model has unsaved changes, you are asked first; *Cancel* or kbd:[Esc] keeps it. If the Aspect Model is already open in another tab, that tab is activated instead.
* *Open in new tab*: to open the Aspect Model in an additional tab of the current window
* *Find elements*: to opens the Find elements section
* *Copy file path*: to copy the file path to the clipboard
* *Delete*: to delete the Aspect Model from the workspace (see <<delete-aspect-model>>)

image:workspace-action.png[,40%]

If you just select another Aspect Model, it will not be loaded but its elements will be listed in the left sidebar.

== Create a namespace

You can create a namespace manually on your local machine, or automatically by using the Aspect Model Editor.

* The easiest way to do this is to click on the File menu, select one of the *New...* menu items, and later click *Save to Workspace*. A namespace folder will automatically be created on your file system, and the Workspace will display it respectively.
* If you import a zip file with models into your workspace, and it contains valid models with namespaces which
did not exist in your workspace yet, these will be created additionally.

TIP: In case you have manually added or deleted a file on your local Aspect Model Editor file directory it might happen
that the change is not instantly visible on the Workspace. In such a case click the *refresh* icon to update the Workspace view.

[[delete-aspect-model]]
== Delete an Aspect Model

Before an Aspect Model file is deleted, the Aspect Model Editor checks whether any other file of the workspace still uses one of its elements.

* If another file references the Aspect Model, the deletion is blocked. A dialog lists the referencing files and the referenced elements. Remove these references first.
* It does not matter whether the Aspect Model itself uses other files. Only *incoming* references block the deletion.
* An Aspect Model that is open in a tab or in another Aspect Model Editor window cannot be deleted. Hover over the disabled *Delete* entry to see the reason.

By deleting the last Aspect Model of a namespace, the folder will be deleted as well.

[[delete-namespace]]
== Delete a namespace

Use the three-dot menu next to a namespace and select *Delete namespace* to delete all Aspect Models of this namespace version at once.

* The Aspect Model Editor checks whether Aspect Models of *other* namespaces (or other versions of the same namespace) reference elements of this namespace version. If so, the deletion is blocked and the referencing files are listed.
* References between the files of the namespace itself do not block the deletion.
* Files that cannot be read are listed as well and also block the deletion, because their references cannot be checked.
* If no references are found, a warning shows the number of Aspect Models that will be deleted. The deletion must be confirmed.
* A namespace cannot be deleted while one of its Aspect Models is open in a tab or in another Aspect Model Editor window. The tooltip of the disabled entry tells you why.

Only `.ttl` files are deleted. Empty namespace and version folders are removed afterwards.

[[clear-workspace]]
== Clear the workspace

The *Clear workspace* icon in the header of the Workspace sidebar deletes all Aspect Models of the workspace.

* Type `CLEAR` into the confirmation field to enable the *Clear workspace* button.
* By default a backup (ZIP file) of the workspace is created in the workspace folder first. You can disable this option in the dialog.
* No reference check is needed, because all Aspect Models are deleted.
* The action is disabled while an Aspect Model of the workspace is open in any Aspect Model Editor window, or when the workspace is empty. The tooltip of the icon tells you why.
* Folders of namespaces and versions that are left empty are removed as well.

NOTE: The check of other windows is only available in the desktop application. In the browser, only the tabs of the current window are checked.

== Troubleshooting
=== Aspect Model is marked with a red exclamation mark
Let us assume you have manually added a new ttl file to the namespace folder on your local file directory
reserved for the Workspace.

As the file was most probably not created in scope of that namespace, the Aspect Model Editor shows the error marker,
as it will not be able to load this Aspect Model.

In such a case you will need some expert who can fix it with a text editor.
